# 三人聚智 0.2.3

本版调整 Windows 升级恢复材料的保留方式：安装及用户资料恢复成功后自动清理整个固定备份目录，失败时保留恢复材料，避免升级成功后长期积累旧副本。Windows NSIS 与 macOS DMG 更新流程继续独立维护和验收。

## 成功后清理

- 用户目录恢复完成并持久化提交后，单独执行清理阶段；成功时删除本次旧程序、已核验的历史与中断材料、日志及固定备份目录。
- 安装器在资料提交成功后停止退出回滚，避免退出回调再次创建空备份目录。
- 先核验整个备份布局与链接，再核对历史用户文件在当前安装中的类型、大小和 SHA256，全部通过才清理。已确认的旧发行程序可清理，未知顶层文件按用户资料处理。
- 旧历史与中断材料中的独有文件、不同内容或链接会保留并明确提示；不覆盖当前文件，不把用户已删除的插件自动补回，也不把备份改名搬到另一位置继续累积。
- 清理失败与安装失败分开：新版及用户资料已恢复时，可以重试清理，取消清理仍正常完成安装；保留的材料供核查，下次升级不会因此被误回滚。
- 已提交事务中仍有未核实旧资料时，再次升级只将其原子收纳到同一固定目录的恢复区，继续保留原字节，不覆盖当前配置，也不在准备新事务时盲删。收纳记录可覆盖移动前后中断，重试不重复归档。
- 中途占用或清理中断时保留提交记录，支持继续清理；目录已经不存在时重复清理和退出回调均不重建目录。

旧版复制备份导致安装缺文件时，仍保留对本次直接旧格式失败备份的单次补缺兼容，不从永久历史反复恢复旧插件。

## 验证范围

使用唯一随机 GUID、独立注册表和隐藏的微型载荷验证事务及完整 NSIS 安装器，覆盖成功无备份、失败保留、清理中断重试、历史独有与冲突、链接保护，以及清理失败不回滚已安装版本。中文进程关闭、长路径、跨盘 TEMP、当前用户和全用户安装、真实旧卸载、解包后回滚与重试继续保留。

本机历史备份的逐文件审计仅保存在被排除的本地构建目录，不将插件数据、文件清单或原始扫描报告公开。

四个目标的构建、公开范围检查和隔离运行验收通过后由 GitHub Actions 发布；具体结果见 [Actions](https://github.com/yuhanbo758/sanrenjz/actions/workflows/package.yml) 和 [0.2.3 Release](https://github.com/yuhanbo758/sanrenjz/releases/tag/v0.2.3)。

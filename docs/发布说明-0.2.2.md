# 三人聚智 0.2.2

本版修复 Windows 已完成资料备份却仍反复弹出“程序无法关闭”、重试不能继续安装的问题，并停止在安装目录旁反复生成历史备份文件夹。

## 完整链路根因

0.2.1 的长路径复制已能完成备份，但旧 electron-builder 卸载器仍会再次遍历原安装树，把文件逐个移到自己的临时目录。深层路径迁移失败后，父安装器将任意旧卸载非零退出统一显示为“程序无法关闭”。相同文案也用于进程检查和载荷复制失败，不能仅凭文案判断确有进程占用。

现场没有宿主进程，旧全用户安装记录仍为 0.1.9。完整原生安装器测试复现了旧卸载返回 2，证明只验证备份宏不能证明覆盖升级成功。此前使用空进程检查和模拟目录删除的测试已移除。

## 固定目录事务

1. 用户确认安装目录并关闭程序后，把旧安装目录整体同盘移动到固定事务目录的 `active/app`，不重复复制整套插件及缓存。
2. 原安装位置只留旧卸载器空壳，调用真实旧卸载流程；子卸载器的临时目录与安装盘一致，父安装器继续使用已初始化的短临时目录。
3. 新版程序解包后，把插件、Python 环境、运行资料及新载荷中不存在的旧顶层资料移回；核对事务状态后清理已替代的旧程序。
4. 取消或失败时恢复原目录及本产品原注册表范围。恢复使用持久日志，覆盖部分移动、提交清理中断、跨版本重试等状态。

固定目录仍位于安装目录之外，避免被旧卸载器删除。历史材料集中在同一个目录的 `legacy` 下；普通重试复用同一事务，不新增同级 `previous-*`。旧失败备份只在本次迁移中补缺一次，不覆盖当前文件，也不会在未来升级时复活用户已删除的插件。

Windows 使用系统自带 Windows PowerShell 5.1 和原生文件移动 API；系统 API 直接在内存声明，不再依赖 CodeDOM 在临时目录编译，避免英文 Windows 云端环境下中文 TEMP 导致初始化失败。不安装 Python 或新增第三方运行依赖。Mac 安装更新代码保持独立，继续沿用 DMG 校验、应用替换及启动确认流程。

## 验证

- 使用唯一随机 GUID、独立测试注册表和微型载荷，真实构建新旧 NSIS 安装器，保留实际进程检查、旧卸载器、解包、安装记录和失败回调。
- 覆盖中文宿主关闭、长路径旧版失败基线、当前用户与全用户覆盖升级、解包后失败回滚、同目录重试、首次安装、初始化取消及跨盘 TEMP。
- 9 项真实 Windows PowerShell 故障测试通过，包含部分恢复、提交清理锁、原目录已恢复但标记未更新、跨版本恢复、旧历史导入中断、注册表原类型与值集合恢复，以及拒绝未知非应用目录。
- 本机实际全用户安装已从 0.1.9 覆盖到 0.2.2，真实安装器退出 0，程序包和安装记录均为 0.2.2。
- 本机升级前后核对 5,936 个插件、运行资料及既有备份文件的 SHA256：无缺失、无变化；设置文件保持原字节。新卸载器及图标属于被更新的程序文件，不纳入用户资料相同字节断言。
- 本次 active 事务清理完成，同级 previous 目录为零；原有历史均已集中保留。安装没有自动启动业务插件。

本机原始审计、哈希和事务测试报告只保留在被排除的构建目录，不公开用户数据。公开状态见 [GitHub Actions](https://github.com/yuhanbo758/sanrenjz/actions/workflows/package.yml) 和 [0.2.2 Release](https://github.com/yuhanbo758/sanrenjz/releases/tag/v0.2.2)。

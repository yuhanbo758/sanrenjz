# 三人聚智 0.2.0

## Windows 安装更新修复

- 修复中断安装或取消后留下升级备份，导致后续安装持续被阻挡的问题。
- 用户确认最终安装目录并正式安装后才备份；开始备份前检查宿主运行状态，备份成功后才卸载旧程序。
- 检测到旧恢复材料时先改名独立归档，不覆盖当前插件、不删除旧备份；完成安装后告知归档位置。
- 保留两类插件、插件运行资料、旧配置及按需 Python 环境。备份或恢复失败明确返回失败，并保留恢复材料。

## 平台和既有功能

- Windows x64 使用 NSIS EXE；macOS Intel x64、Apple Silicon arm64 分别提供 DMG 和 ZIP；Linux x64 提供 AppImage 和 tar.gz。
- macOS“安装并重启”继续使用独立镜像校验、同盘 `.app` 替换、失败回滚和新版启动确认流程。Mac 构建、签名及安装更新逻辑与 Windows 安装事务分别验收。
- 同步已有插件管理卸载改进，保留独立配置和业务数据，阻止卸载运行中的插件，并尊重内置插件卸载记录。
- 同步 macOS 插件 Dock 身份、Python 插件图标及宿主启动兼容改进，保留 0.1.13 的连续文本插入修复。

## 版本递增

本次从 0.1.13 显式升级到 0.2.0。以后末位版本号只使用 0～9：0.2.0 的下一版为 0.2.1，0.2.9 的下一版为 0.3.0。

维护者使用 `npm run version:next` 预览；发布获授权后，加 `-- --apply` 同步 package.json 和 package-lock.json。Actions 校验版本与锁文件，不在普通推送时自动增加版本。

## 发布验收

GitHub Actions 在四个原生 runner 构建、检查公开范围和隐私、运行隔离验收；Windows 另执行真实 NSIS 生产宏的升级备份回归。只有四目标全部通过，才按来源提交发布 7 个安装包、SHA256SUMS.txt 和 release-manifest.json。

本机验证和问题根因见 [Windows 修复记录](windows-installer-update-20261111.md)。实际公开状态以 [Actions](https://github.com/yuhanbo758/sanrenjz/actions/workflows/package.yml) 和 [0.2.0 Release](https://github.com/yuhanbo758/sanrenjz/releases/tag/v0.2.0) 为准。

默认包不包含私有插件、真实配置或 Python 运行时。Windows 当前未作正式代码签名；Mac 采用 ad-hoc 签名，未使用 Developer ID、未经 Apple 公证。原生构建和隔离检查不能替代用户设备上的全部安装、权限与业务验收。

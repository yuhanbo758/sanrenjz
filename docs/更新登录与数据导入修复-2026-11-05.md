# 更新、登录与旧版数据导入修复

本次保留应用版本 `0.1.7`，在修复分支维护；尚未提交、推送或替换 GitHub 已发布资产。已发布的原 `0.1.7` 不包含本次修复，需要先手动安装本地修复包。两个来源项目只读，未对真实用户数据执行迁移。

以上描述本地修复包交付时的状态。后续经用户授权，将这批修复纳入 `0.1.8` 正式发布，见 [0.1.8 发布说明](发布说明-0.1.8.md)；原 `0.1.7` 标签及资产保留。

## 功能变化

- **应用更新**：移除合并初期的硬编码阻断及旧产品更新地址。用户主动检查 `yuhanbo758/sanrenjz` 的正式 Latest，按 Windows x64、macOS x64/arm64、Linux x64 精确选择资源。与商店登录、会员权限独立，不自动下载或安装。下载支持取消、超时和失败重试，先暂存，再校验大小及 SHA256；打开安装包前重新校验。Windows 显式启动安装，macOS 打开 DMG，Linux 定位 AppImage。提供发布页面入口和中文错误提示。
- **登录同步**：商店已改用 HttpOnly Cookie，旧宿主仍依赖 `localStorage.token`，因此网页已登录而主界面未识别。现在使用同一个商店 Session 查询账号，Cookie 明确返回 401 才兼容旧 Bearer；有效用户信息与两类权限分别验证。服务故障保留已确认账号并标记待确认。退出期间使在途请求失效，阻止旧页面或 Cookie 变化重新恢复账号；清理失败明确提示并可重试。新登录不把 Cookie 复制到文件，也不新增明文令牌存储。
- **数据导入**：设置侧栏新增“数据导入”，分别展示旧效率工具与旧 Python 程序管理。可以自动检测，或手动选择旧安装、便携、插件及用户数据目录。先预览，再选择插件、配置、插件显示与搜索偏好；旧解释器默认不选。先备份，只补缺少项，现有程序和配置保持不变，同名冲突列入结果。旧 Python 插件旁的配置可按原稳定 ID 补入统一目录，即使同名程序已内置也不会遗漏配置。

迁移不复制登录凭据、Cookie、Python 运行时或虚拟环境，不导入全局快捷键、系统自启动或旧插件自启动。原始插件存储命名空间、Python 配置 ID、嵌套数据库与 `.enc` 保留。已有解释器选择与明确偏好优先；共享配置目录无需重复复制。路径越界、目标链接及复制失败均有隔离检查，失败保留备份和报告。

## 使用入口

1. 安装本地修复包后，进入“设置 → 数据导入”。
2. 点击“重新检测旧应用”，未检测到时选择旧应用目录。可分别处理两个旧产品，也可多选目录。
3. 点击对应来源的“预览并选择”，检查应用目录、用户数据目录和自定义配置目录。
4. 选择要导入的项目，点击“备份并导入所选内容”。查看新增、保留、冲突和备份位置；可以重复导入。

导入操作独立执行，不替用户保存其他设置页的待保存输入，也不会运行插件或业务任务。需要自启动时，请在新应用的插件管理中明确启用。

- 数据导入设置页：29 条隐藏 Electron 断言通过，包括手动选择、无来源、失败重试、重复操作阻止、冲突与备份报告、未保存输入保留，以及两种窗口宽度。
- 迁移管理器隔离回归通过：来源识别、配置别名、同名内置插件、稳定 ID、偏好合并、旧自启禁用、现有配置保留、重复迁移、越界与链接拒绝、虚拟环境排除及失败回滚。
- Electron 25.9.8 真实联网检查正式 Latest 成功，当前版本 `0.1.7` 正确返回无更新；没有触发下载安装。
- Windows 公开构建、实际打包程序验收和隐私检查的原始结果保留在本地 `dist/`，不进入公开仓库。新回归已接入 Actions；本次未触发远端构建。
- Windows 实际打包程序 31 条断言通过，包括隔离 Python 文件的真实启动、中文日志、统一搜索、设置及退出清理。公开候选 679 个文件与构建暂存 496 个文件均无未处理隐私问题；构建时 5,992 项审计通过，首次运行复制公开插件种子后 6,436 项复审亦通过。
- 原基线中其余 2,493 个受保护文件逐个保持一致、无缺失；主设置文件在检查期间更新过一次，未用旧基线覆盖当前设置。该差异及当前文件校验值另存本地报告，不能将旧枚举路径变化误报为受保护文件被修改。

首次并发回归曾在启动验收成功报告后的 Electron 原生退出阶段出现一次 `0xC0000005`。后续三个隔离启动及最终完整回归未复现，具体根因尚未证实；设置副作用测试已补齐商店 Session 的外网隔离，没有跳过断言或忽略非零退出码。

后续 0.1.8 云端回归再次复现该异常。对照发现测试在 Electron 的 quit 事件内删除用户数据目录；旧方式24次并发运行有5次异常，改由父进程在子进程完全结束后清理，同样24次全部正常退出。修复仅涉及测试目录的分配和清理，不更改业务退出逻辑，不以强制成功退出或重试掩盖错误。

## 交付与边界

没有替用户执行真实账号登录、实际旧数据导入、安装覆盖或应用重启；macOS/Linux 本次未进行实机迁移与安装验证。系统签名及安装升级验收与源代码、解包程序测试分别记录。

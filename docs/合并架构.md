# 合并架构

主进程与原生页面延续效率工具架构。`app/merged-host.js` 注册统一插件、环境和迁移 IPC；原效率 PluginManager 继续负责效率插件，`PythonManager` 单独负责 Python 进程。

## 接口与数据流

统一目录条目包含 `id/engine/name/path/description/iconPath/category/version/hidden/autoStart`；两类 ID 分别以 `tools:` 和 `python:` 开头。两种旧清单原样保留，不互相转换。主页面过滤当前引擎，全局搜索聚合两类目录；Python 不自动添加剪贴板超级面板动作。

`unified:list/run/stop/remove/import/preference` 处理统一入口；`python:status/discover/select/select-path/install/cancel/diagnose/logs` 处理环境和日志。IPC 返回运行时信息时只传可展示字段，不把子进程完整环境变量发送给页面。

`app/run-log-store.js` 统一缓存两类运行日志。效率管理器通过构造参数 `onLog` 上报带 `tools:` ID 的生命周期、窗口控制台及 JS 输出；Python 的 `onLog` 同时写入统一缓存并保留旧 Python 通道。`runtime:logs` 提供记录与来源目录，`runtime:log` 推送新记录，`runtime:export-logs` 按类型/稳定 ID 导出；浏览不校验解释器或写用户设置。默认仅保留本次会话的最近 4,000 条，并限制单条和总字符数；包含隐藏来源及缓存中仍有记录的历史来源。

设置 `pythonMode` 为 `none/custom/managed`，默认 `none`。自定义解释器使用 `customPythonPath`，按需安装使用 `managedPythonPath`。选择、校验失败不改变原选择；安装中禁止竞争选择；退出会取消安装并等待暂存清理。环境变量只为对应子进程构造，清除其他 Python 环境污染。

Python 管理器通过当前解释器的包元数据检查标准 requirements，展示缺失依赖后再安装，不使用 PATH 中的 pip。进程状态、stdout/stderr 和停止操作绑定同一管理记录；退出按进程树清理。

继续注入 `YUHANBOPY_PLUGIN_CONFIG_FILE`、`YUHANBOPY_PLUGIN_CONFIG_DIR`，并提供 `SANRENJZ_SETTINGS_FILE`、`SANRENJZ_PYTHON_PLUGIN_DIR`。新版公共 bootstrap 保留原插件目录导入优先级。标准独立启动器使用新宿主设置，自定义辅助文件只能明确审查后适配。

## 迁移与公开范围

迁移器仅在用户选择后复制旧插件、所选配置目录和有效自定义解释器路径。复制前备份目标，已存在条目不覆盖，来源不删除。新增标准 Python 辅助文件在新副本适配；含自定义启动器或入口歧义的情况显示未自动适配。浏览器 Cookie、账号令牌和旧 Python 运行时不迁入。

公开插件允许清单与私有清单分开维护。公开打包先创建受控暂存，再运行 electron-builder 并检查实际 ASAR/资源目录，避免 `.gitignore` 与安装包规则不一致。新插件未登记时不能自然进入公开包。

新应用无发布凭据、远端、自动发布工作流或旧主程序更新通道。旧工作流只作为本地参考文本保存，不会执行。

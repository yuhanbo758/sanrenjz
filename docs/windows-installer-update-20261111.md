## Windows 根因及平台边界

`build/installer.nsh` 原先在 `customInit` 中备份安装目录。该阶段早于交互式安装目录确认；打开安装器后取消、备份失败或后续安装失败，都可能留下固定的 `.sanrenjz-update-backup`。下一次初始化只要发现该目录就中止，因此正常升级过的机器也会在一次中断之后持续被阻挡。

这段 Windows 逻辑从公开提交 `600e1a7`（2026-11-04）起未被后续 macOS 更新改动修改。它在私有最初快照与本次拉取的远端中也保持一致，现有证据不支持将截图错误归因于 Mac 更新改动。

Actions 使用独立的 Windows x64、macOS x64、macOS arm64 和 Linux x64 原生 runner；实际构建参数分别指定平台与架构。Windows 使用 NSIS EXE；Mac 使用 DMG/ZIP，独立执行签名、镜像挂载、`.app` 替换与启动确认。Mac 的原生编译和签名钩子遇到 Windows 目标直接返回。

2026-11-11 核对 [Actions 42928074733](https://github.com/yuhanbo758/sanrenjz/actions/runs/42928074733)：四目标构建及发布均成功。此前 [Actions 42927416686](https://github.com/yuhanbo758/sanrenjz/actions/runs/42927416686) 的失败是共用入口未接受 `--publish never` 参数，四平台均失败；该问题已由远端修复，与本次截图的运行期安装阻断不同。构建成功本身不证明中断后重新升级已被验收。

- 残留固定备份先原子改名到唯一的 `.previous-*` 同级路径；不覆盖当前插件，不自动合并可能陈旧或不完整的恢复材料。
- 为本次安装重新备份四个现有目录：`plugins`、`python-plugins`、`plugin-configs`、`runtime`。恢复全部成功后才清理本次备份；旧归档继续保留，并在交互安装完成时告知位置。
- 创建目录、备份或恢复失败会报告非零退出，备份失败不进入旧版卸载；静默安装使用默认消息响应，避免等待不可见弹窗。
- 独立用户数据目录仍由原安装策略保留，未修改 Mac 安装更新代码。

# 三人聚智 0.2.1

本版修复 Windows 安装期间“无法完整备份 plugins”的长路径问题，完整保留插件及 `.runtime` 资料。

## 已验证根因

0.2.0 解决了残留升级备份阻挡再次安装的问题，但仍沿用 NSIS Shell `CopyFiles`。实际阅读插件包含 5,010 个文件，源文件最长路径 241 个字符；加上备份目录后，目标路径达到 264 个字符，触发 Shell 复制的路径限制。文件可读性检查没有发现占用导致的读取失败，现场也没有目录联接。

新增最小回归在 0.2.0 代码上复现相同失败：源路径 250 个字符，备份路径 273 个字符，安装在备份阶段返回 2。之前的短路径夹具没有覆盖这个真实场景，因此 0.2.0 的通过记录不能证明深层运行目录可完整升级。

## 修复

- 备份和恢复改用 Windows 自带 Robocopy，保留文件、属性、时间戳与空目录，按原生返回码判断成功和失败，不启用目标镜像删除或移动源文件。
- 每个目录的复制失败都保留返回码与 UTF-16 本地日志，日志只用于定位文件系统错误，不读取或输出插件配置内容。
- 备份清理同样使用扩展路径，避免复制完成后长路径文件仍留在固定备份目录。
- 卸载旧版前检查符号链接、目录联接及路径属性；遇到无法安全处理的链接时停止，防止旧卸载器递归删除外部目标。
- 原有取消安装、最终安装目录确认、旧备份归档和失败保留恢复材料的规则继续有效。Mac 安装更新代码保持原样，继续独立构建和验收。
- 维护者显式递增版本改用 `npm run version:bump`，避免 PowerShell 的 npm 转发丢失追加参数；版本工具保留文件原有换行符，不改动依赖版本。

实现参考：[Microsoft Robocopy 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/robocopy)。

## 实际目录验证

在本机用生产 NSIS 备份与恢复宏读取实际安装目录，恢复到隔离目录，没有启动任何业务插件、没有卸载或覆盖现有安装。

- 共 5,903 个文件，491,010,998 字节。
- 源目录运行前后全部文件 SHA256 一致。
- 隔离恢复的所有文件 SHA256、文件数和目录集合与源目录一致。
- 恢复路径最长 304 个字符，备份清理成功，NSIS 退出码 0。
- 原生回归覆盖长路径、隐藏文件、空目录、成功返回码、目标额外文件保留、独占文件锁失败、重试及目录联接拒绝；失败夹具均在旧卸载器执行前停止或保留备份。

本地原始路径、复制日志、审计报告和业务目录副本只保留在被排除的运行/构建目录，不纳入 Git 或安装包。发布结果以 [GitHub Actions](https://github.com/yuhanbo758/sanrenjz/actions/workflows/package.yml) 和 [0.2.1 Release](https://github.com/yuhanbo758/sanrenjz/releases/tag/v0.2.1) 为准。

默认公开包继续排除私有插件、真实配置和 Python 运行时。Windows 使用 NSIS EXE；Mac 两种架构分别使用 DMG/ZIP，沿用 ad-hoc 签名和独立应用替换流程。
